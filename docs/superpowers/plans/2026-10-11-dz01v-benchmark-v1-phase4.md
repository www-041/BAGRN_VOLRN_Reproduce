# DZ01V Benchmark V1 Phase4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add immutable Phase3-linked independent TEST second review, audited formal TEST export, and a synthetic-only six-method DEVELOPMENT interface for the four trial pairs.

**Architecture:** A read-only frozen snapshot loader is the sole authority for identities and roles. An append-only second-review store and policy module sit beside the existing annotator; a separate exporter validates the whole chain before any formal TEST truth is emitted. A DEVELOPMENT-only adapter contract consumes only the 43 frozen DEVELOPMENT truth rows and produces normalized four-pair method results without launching methods in this phase.

**Tech Stack:** Python 3.11, Tkinter, csv/json/hashlib, rasterio, numpy, existing `benchmark_phase2_core` and `registration_benchmark` helpers, pytest; PowerShell commands for the local `.venv-registration` environment.

**Spec:** `docs/superpowers/specs/2026-10-11-dz01v-benchmark-v1-phase4-design.md`

## Global Constraints

- Four trial pairs only: `00_01`, `02_03`, `05_07`, `08_10`; frozen counts 43 DEVELOPMENT, 84 TEST candidates, 33 UNASSIGNED.
- Never write the four `docs/benchmark/v1/phase2/auto_candidates/*.csv`, first-review files, any Phase3 artifact, B9 inputs, or Task15/Task16 outputs.
- Preserve EPSG:32650 origin `(0,0)` m, 10,000 m cells, strict 500 m inset, and DEVELOPMENT iff `(ix+2*iy)%3==0`; never reassign an existing frozen role.
- All second-review tests use synthetic records and disposable paths; no real TEST review event is generated by tests or smoke checks.
- No six-method execution or TEST scoring in Phase4 preparation. KARIOS/AROSICS remain `NOT_VERIFIED_END_TO_END`; AROSICS local mode is separate from the global-translation main comparison.
- All paths default from repository root. A corrupt/missing file or hash/identity mismatch hard-stops the relevant workflow; no silent manual-mode fallback.
- Git metadata is currently read-only in this workspace (prior `index.lock` permission denied). Do not stage/commit during execution unless that permission is explicitly restored; preserve every unrelated untracked file.

## Review Focus

1. A CSV with a duplicate `(pair_id,candidate_id)` or swapped scene IDs must hard-stop before the GUI opens — Task 1 test.
2. A truncated/replayed JSONL event or a second reviewer reusing the first reviewer's identity must not yield formal truth — Task 2 test.
3. A coordinate exactly on the 500 m inset boundary, or a point moved back after one invalid adjustment, must remain ineligible — Task 2 test.
4. A candidate approved by a human but spatially invalid, disputed, or lacking a non-use attestation must appear in exclusions, not in formal truth — Task 4 test.
5. A matcher result in target-to-reference orientation, a missing method/pair, or a failed method must not silently become a successful DEVELOPMENT score — Task 5 test.
