# Phase4 independent second-review record

The frozen Phase3 assignment and the four Phase2 candidate CSVs are read-only. A real second reviewer writes only `docs/benchmark/v1/phase4/second_reviews/<pair_id>.jsonl`. This directory remains empty until a researcher actually reviews a point. Synthetic tests use temporary directories and never populate it.

Each UTF-8 JSON line is one immutable event, with `schema_version=phase4_second_review_v1`, `event_id` (UUID), `previous_event_sha256`, `reviewed_at_utc`, `pair_id`, `candidate_id`, `frozen_role=TEST`, `frozen_grid_cell_id`, `phase3_assignment_sha256`, and `source_candidate_sha256`. Audit fields include `reviewer`, `first_reviewer`, `first_review_status`, `first_confidence`, explicit `inspections.left_original_resolution` and `.right_original_resolution`, `human_outcome` (`APPROVED`/`REJECTED`/`DOUBTFUL`), new `human_uncertainty`, `adjusted`, `adjustment_reason`, `before` and `after` positions (`row`, `col`, `x`, `y` for each image), `delta_pixels`, `material_disagreement` (`YES`/`NO`), `disagreement_note`, `spatial_status`, and `spatial_reasons`.

`APPROVED` is a human decision, not a geometry pass. `NOT_ELIGIBLE_AFTER_COORDINATE_ADJUSTMENT` is sticky once any attempted adjustment fails the original 500 m safe-core, same-cell, valid-mask, or 1 km DEVELOPMENT/TEST isolation check. A later return to the original coordinate does not clear it. A material disagreement requires independent adjudication outside this Phase4 exporter. Neither a `TEST` role nor a high first-review confidence counts as second approval.

The JSONL hash chain detects accidental or unauthorized in-place edits relative to its next event and frozen source hashes. It does not establish a reviewer's real-world identity or cryptographically prove that a person inspected an image; those require human governance. Only the second reviewer may explicitly attest to both image inspections. A competing writer or damaged last line hard-stops append. No event is automatically generated from candidate score, initial confidence, or Phase3 role.

## Formal TEST export evidence

The explicit non-use attestation is a JSON object with `dataset_version` equal to the Phase3 assignment SHA256; nonempty `responsible_person`, `signature`, and `run_ids`; `excluded_test_ids` containing exactly all 84 frozen TEST candidate IDs; and `declared_no_test_use: true`. It states that no TEST IDs or coordinates entered geometric model fitting, RANSAC selection, threshold choice, or parameter tuning. This is a human research declaration, not independently provable software telemetry. Missing or inconsistent evidence excludes every point.

The formal exporter returns two files only on an explicit export request: `formal_test_truth.csv` for independently approved and spatially valid TEST points, and `formal_test_exclusions.csv` for all other frozen TEST points with `reasons` joined by `|`. Their row counts must sum to 84. `formal_test_status.json` records eligible and excluded totals. For read-only inspection, use `--preflight`: no truth or exclusion file is written. The old Phase2 auto-truth CSV is not accepted as the Phase4 formal TEST source.
